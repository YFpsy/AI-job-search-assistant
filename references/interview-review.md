# 面试记录与复盘

## 原始材料

- 用户提供录音时，先确认当前环境是否能转写；不能时请用户提供转写文本，不假装已经听取。
- 录音和转写原件保持不变，另建结构化复盘。
- 尊重用户提供的录音边界，不主动上传或公开个人和公司信息。

## 复盘流程

1. 确认岗位编号和面试轮次，分配面试编号。
2. 从转写中按顺序提取面试官问题、用户原始回答、追问和可识别反馈。
3. 对每个问题分析：可能考察什么、回答是否回应、事实是否清楚、本人贡献是否准确、逻辑和表达哪里可改。
4. 给出可以直接练习的改进思路。参考回答只能重组用户已经提供的事实；缺失处标待补。
5. 整理用户做得好的部分、可改进部分、暴露的能力或准备缺口，以及下一次可执行动作。
6. 识别公司、岗位、领导风格、团队氛围或加班倾向的信号时，保留触发判断的原话或行为，并分为：已确认事实、本人感受、AI 推测、待验证问题。
7. 向用户展示复盘摘要并确认。确认后写入岗位档案和 `面试记录.xlsx`。

## 知识沉淀

用户确认后才进行跨文件更新：

- 新的真实经历或细节 → `00_个人资料/过往经历/`；
- 可复用回答思路 → 对应经历文件或面试准备文件；
- 新发现的工作偏好与边界 → `个人档案.md`，保留来源和日期；
- 本场面试数据与下一步 → `面试记录.xlsx` 和 `_当前求职状态.md`。

不把面试官的一句话直接当作行业规律，也不从一次失败推断用户长期能力。
