# 知识库结构与初始化

## 目标结构

```text
AI求职知识库/
├─ AGENTS.md
├─ _知识库索引.md
├─ _当前求职状态.md
├─ 00_个人资料/
│  ├─ 个人档案.md
│  ├─ 自我分析/
│  ├─ 过往经历/
│  └─ 简历版本/
├─ 01_求职过程/
│  ├─ 投递记录.xlsx
│  ├─ 面试记录.xlsx
│  └─ 岗位档案/
└─ 02_外部参考/
   ├─ 行业观察/
   └─ 求职方法/
```

## 初始化步骤

1. 确认当前工作区就是用户准备使用的 Vault 根目录。不得默认使用桌面、文档目录或其他推测路径。
2. 检查目标不是磁盘根目录、用户主目录或包含大量无关文件的上级目录；有疑问时暂停确认。
3. 运行 `scripts/init_vault.py --vault <当前Vault绝对路径>`。
4. 脚本只能创建缺失目录和缺失文件；同名文件存在时必须跳过，不得覆盖。
5. 重新检查三层目录、三个根目录 Markdown 文件和两个工作簿是否存在。
6. 告诉用户创建了哪些内容、跳过了哪些已有内容，并提出第一个建档问题。

## 两个工作簿的职责

### `投递记录.xlsx`

一行对应一个岗位，用于记录完整投递漏斗。重点关联岗位编号、公司、岗位、投递渠道、简历版本、当前状态、最高进度和反馈时间。

### `面试记录.xlsx`

一行对应一场面试。同一个岗位可以有多轮面试，每一轮都有独立面试编号，并关联转写和复盘文件。

工作簿只保留适合横向比较的字段。长篇 JD、逐字稿、准备内容和复盘正文放在岗位档案中。

## 岗位档案创建时机

所有岗位都进入投递记录，但不为每一条记录预先建立空文件夹。当用户需要分析 JD、定制材料、准备面试或保存复盘时，创建：

```text
01_求职过程/岗位档案/J001_公司_岗位/
├─ JD原文.md
├─ 岗位分析.md
├─ 投递材料/
├─ 面试准备.md
├─ 面试记录/
└─ 结果记录.md
```

只创建当前阶段真正需要的文件；不要一次生成所有空文档。

## 编号规则

- 从现有 `投递记录.xlsx` 和岗位目录中寻找最大编号，再顺延生成新岗位编号。
- 同一公司同一岗位、同一招聘链接或同一份 JD 疑似重复时，先询问用户，不直接新建。
- 面试编号由岗位编号和该岗位的面试顺序组成，例如 `J003-M02`。
- 文件夹名称中的非法字符只做必要替换，不改写公司或岗位名称。
